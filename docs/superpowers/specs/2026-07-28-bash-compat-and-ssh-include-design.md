# Bash version gate, macOS-only UseKeychain, and Include-based SSH config

## Problem

An independent production-grade audit found three related High-severity defects that break the tool for its own stated supported platforms:

1. `${var,,}` (case conversion) is bash 4.0+ syntax, but the shebang is `#!/usr/bin/env bash`, which on a stock macOS machine with no Homebrew resolves to Apple's bash 3.2.57. The very first interactive prompt in `setup` fails with `bad substitution`.
2. `UseKeychain yes` is written unconditionally into every generated SSH host block. It's a macOS-only OpenSSH extension — on Linux (`install.sh` explicitly supports Linux) it's a fatal ssh_config parse error that breaks `ssh` globally, not just for git-smart.
3. Host blocks are appended (`cat >>`) to the end of `~/.ssh/config`. ssh_config is first-match-wins, so a pre-existing `Host *` or `Host github*` block earlier in the file silently takes priority — the tool can authenticate as the wrong GitHub identity while reporting success. Verified directly with `ssh -G`.

## Goals

- `git-smart` refuses to run on bash < 4 with a clear, actionable error instead of a confusing mid-script failure.
- `UseKeychain` only appears in generated SSH config on macOS.
- Git-smart's SSH host blocks always take priority over anything else in the user's `~/.ssh/config`, regardless of what else is in that file or in what order.
- `doctor` can detect when the *effective* SSH identity (what `ssh` actually resolves) doesn't match what git-smart intended.

## Non-goals

- No attempt to make the codebase run correctly on bash 3.2 — version-gating is the chosen approach (explicit user decision), not a rewrite.
- No general "detect and auto-migrate any tool's legacy config" framework. The one-time migration of *this machine's* already-existing git-smart-managed blocks (written by earlier sessions before this fix existed) is a manual, one-off step, not new code.
- No changes to how `github-personal`/`github-work`/bare-`github.com` alias *names* are chosen — only how the underlying SSH config text is generated and stored.

## Design

### Bash version gate

Immediately after `set -euo pipefail`:
```bash
if (( BASH_VERSINFO[0] < 4 )); then
  printf '[!] git-smart requires bash >= 4 (found %s). On macOS: brew install bash\n' "$BASH_VERSION" >&2
  exit 1
fi
```

### New constants

```bash
GIT_SMART_SSH_INCLUDE_DIR="${HOME}/.ssh/config.d"
GIT_SMART_SSH_INCLUDE_FILE="${GIT_SMART_SSH_INCLUDE_DIR}/git-smart"
```

### `ensure_ssh_include()`

Ensures `~/.ssh/config` starts with `Include ~/.ssh/config.d/git-smart`. Creates `~/.ssh/config` if missing. If the Include line isn't already present (checked via a simple `grep -qF`), prepends it (plus a blank line) to whatever's already there, via `mktemp` in the same directory + `mv` (atomic, no partial-write risk). Idempotent — safe to call every time git-smart touches SSH config.

### `write_git_smart_ssh_host(host_alias, key_path)`

The single function that replaces `append_ssh_host_if_missing` + `update_ssh_host_identity` + the awk editor:
1. Reads the *current* key path for all three known aliases (`github-personal`, `github-work`, bare `github.com`) from the dedicated file via `current_identity_for_host_config` (repointed at `$GIT_SMART_SSH_INCLUDE_FILE`).
2. Overrides the one being updated with the new `key_path`.
3. Calls `ensure_ssh_include`.
4. Regenerates `$GIT_SMART_SSH_INCLUDE_FILE` from scratch (all three blocks, skipping any with no key path), atomically, `chmod 600`.

Each block is generated by a small helper that includes `UseKeychain yes` only when `uname -s` is `Darwin`.

### Call site changes

- `run_setup`: the ~20-line "compare current vs new, ask to update, else append" branching for personal and work keys is replaced with a direct `write_git_smart_ssh_host "$GITHUB_PERSONAL_HOST" "$personal_key"` / same for work. No confirmation prompt — since this is now git-smart's own fully-owned file, there's nothing risky to confirm; `setup` just prints what it set.
- `apply_global_profile`: its `host_exists`/`current_default` grep+awk branching is replaced with one `write_git_smart_ssh_host "$GITHUB_DEFAULT_HOST" "$key_path"` call.
- `current_identity_for_host_config`: reads from `$GIT_SMART_SSH_INCLUDE_FILE` instead of `$SSH_CONFIG_FILE`.
- `doctor`: in addition to existing checks, compares `identity_for_host` (effective, via `ssh -G`) against `current_identity_for_host_config` (intended, from the dedicated file) for both personal and work, and warns on mismatch. Also checks `ensure_ssh_include`'s state and suggests running `setup`/`global` again if the Include line is missing.

### One-time migration (this machine only, manual, not code)

After implementation: apply the new write path for `personal`/`work`/the global default (populating the dedicated file with the currently-correct key paths), remove the old inline `Host github.com` / `Host github-work` / `Host github-personal` blocks from `~/.ssh/config`, confirm only the `Include` line remains there, and verify with `ssh -G` and `git-smart doctor`.

## Error handling

- `ensure_ssh_include` and `write_git_smart_ssh_host` both use `mktemp` in the *target* directory (not `$TMPDIR`) so the final `mv` is an atomic rename, never a cross-filesystem copy.
- If `$GIT_SMART_SSH_INCLUDE_DIR` doesn't exist, it's created with `chmod 700` before first write (matching `ensure_ssh_dir`'s existing convention for `~/.ssh` itself).

## Testing

No automated test suite in this repo (established convention). Verification: sandboxed `HOME` runs confirming (a) the Include line is correctly prepended and is idempotent on a second run, (b) a fresh sandboxed `setup`/`global` run produces correct dedicated-file content with `UseKeychain` present only when the test simulates Darwin, (c) the shadowing scenario is fixed — a synthetic `~/.ssh/config` with an early `Host *`/IdentityFile block, verified via `ssh -G` that the git-smart-managed alias still resolves to the git-smart-intended key, (d) `doctor`'s new effective-vs-intended check fires correctly on an induced mismatch, (e) the bash version gate correctly refuses to run under bash 3.
