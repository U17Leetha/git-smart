# git-smart fork and pr Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `git-smart fork <owner/repo>` (fork on GitHub via `gh`, clone the fork into the right directory, add an `upstream` remote) and `git-smart pr [--status]` (open or check the PR for the current branch, delegating to `gh`).

**Architecture:** A new shared `require_gh()` guard, plus `run_fork()` (modeled closely on `run_clone()`, reusing `profile_base_dir`/`build_remote_url`/`write_repo_context`) and a thin `run_pr()` that `exec`s straight into `gh pr create`/`gh pr view` once prerequisites are confirmed. Full command wiring (usage text, arg parsing, dispatch) follows the exact pattern already established for every other command.

**Tech Stack:** Bash, matching the rest of `git-smart`'s conventions. No automated test suite in this repo. `fork`/`pr` both call the real `gh` CLI, which normally means real GitHub API calls — this plan avoids that entirely for testing by placing a fake `gh` *shell script* earlier on `$PATH` than the real one, so tests can verify git-smart's own argument routing and local logic (which flags produce which `gh` invocation, how `fork_owner` feeds into `build_remote_url`, etc.) without ever touching a real GitHub account. Combined with `--dry-run` for `fork` (which skips the actual `git clone`), this gives full offline coverage of every line of new logic.

run_fork() {
  local owner repo fork_owner target_dir clone_url upstream_url

  require_gh
  ensure_profile_for_creation

  [[ "$FORK_SPEC" =~ ^[^/]+/[^/]+$ ]] || die "fork requires owner/repo format"
  owner="${FORK_SPEC%%/*}"
  repo="${FORK_SPEC##*/}"

  info "Forking $FORK_SPEC on GitHub..."
  if [[ "$DRY_RUN" -eq 0 ]]; then
    gh repo fork "$owner/$repo" --clone=false >/dev/null
  else
    printf '[*] Dry run: gh repo fork %s/%s --clone=false\n' "$owner" "$repo"
  fi

  fork_owner="$(gh api user --jq .login)"
  target_dir="$(profile_base_dir "$PROFILE")/$repo"
  [[ -e "$target_dir" ]] && die "Target directory already exists: $target_dir"

  clone_url="$(build_remote_url "$fork_owner" "$repo" "$PROFILE")"
  upstream_url="https://github.com/$owner/$repo.git"

  info "Profile      : $PROFILE"
  info "Fork owner   : $fork_owner"
  info "Target dir   : $target_dir"
  info "Origin (fork): $clone_url"
  info "Upstream     : $upstream_url"
  printf '\n'

  if [[ "$DRY_RUN" -eq 0 ]]; then
    mkdir -p "$(dirname "$target_dir")"
    git clone "$clone_url" "$target_dir"
    git -C "$target_dir" remote add upstream "$upstream_url"
    (cd "$target_dir" && write_repo_context "$PROFILE" "$fork_owner" "$(profile_host "$PROFILE")")
  fi

  info "Fork cloned to $target_dir"
  info "Saved profile '$PROFILE' for this repo."
  info "Done."
}

- [ ] **Step 15: Build the fake-`gh` fixture for fully offline testing**

Both `fork` and `pr` normally call the real `gh` CLI, which would mean real GitHub API calls. Instead, build a fake `gh` *shell script* and put its directory first on `$PATH`, so `command -v gh` still finds "a gh" (satisfying `require_gh`) but every invocation is safely intercepted and answered locally — no real network/GitHub access, ever.

```bash
SANDBOX="$(mktemp -d)"
REPO="<your working directory>"
mkdir -p "$SANDBOX/fakebin"
cat > "$SANDBOX/fakebin/gh" <<'EOF'
#!/bin/sh
if [ "$1" = "repo" ] && [ "$2" = "fork" ]; then
  echo "[fake gh] would fork $3"
  exit 0
fi
if [ "$1" = "api" ] && [ "$2" = "user" ]; then
  echo "testowner"
  exit 0
fi
echo "[fake gh] called with: $*"
exit 0
EOF
chmod +x "$SANDBOX/fakebin/gh"
export FAKE_GH_PATH="$SANDBOX/fakebin:$PATH"
```
Keep `$SANDBOX` and `$FAKE_GH_PATH` around for the remaining steps below.
